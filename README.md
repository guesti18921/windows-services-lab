\# Лабораторная работа №15. Службы Windows



\## Цель



Изучить работу фоновой задачи PowerShell и службы Windows на Python, а также сравнить способы управления ими.



\## Состав проекта



\- `win\_monitor.ps1` — PowerShell-скрипт, записывающий сообщение в лог каждые 5 секунд.

\- `py\_service\_wrapper.py` — Python-служба, которая записывает сообщение и PID процесса каждые 5 секунд.



\## Часть 1. Фоновая задача PowerShell



Скрипт размещён в `C:\\Scripts\\win\_monitor.ps1` и зарегистрирован в Планировщике заданий под именем `PowerShellBackgroundMonitor`.



Задача настроена на запуск при загрузке Windows от учётной записи SYSTEM. Для запуска скрипта использован параметр `-ExecutionPolicy Bypass`, действующий для запущенного процесса PowerShell.



Проверка состояния задачи:



```powershell

Get-ScheduledTask -TaskName "PowerShellBackgroundMonitor" |

&#x20;   Select-Object TaskName, State

```



Проверка лога:



```powershell

Get-Content C:\\ps\_service\_log.txt -Tail 5

```



При проверке задача находилась в состоянии `Running`, а лог пополнялся каждые 5 секунд.



Команда:



```powershell

sc.exe query PowerShellBackgroundMonitor

```



вернула ошибку `1060`: задача зарегистрирована в Планировщике заданий и не является службой SCM.



\## Часть 2. Служба Python



Для взаимодействия с диспетчером служб используется библиотека `pywin32`.



Установка библиотеки:



```powershell

py -3 -m pip install pywin32

```



Регистрация и запуск службы выполняются из PowerShell от имени администратора:



```powershell

py -3 C:\\Scripts\\py\_service\_wrapper.py install

sc.exe start PyBackgroundService

```



Проверка состояния:



```powershell

sc.exe query PyBackgroundService

```



Проверка лога:



```powershell

Get-Content C:\\py\_service\_log.txt -Tail 5

```



При проверке служба находилась в состоянии `RUNNING`, а лог пополнялся каждые 5 секунд. В логе также записывается PID процесса.



\## Контрольные вопросы



\### 1. Почему обычный Python- или PowerShell-скрипт нельзя напрямую запустить как службу?



Диспетчер служб SCM ожидает, что программа подключится к нему через механизм служб Windows, зарегистрирует обработчик управляющих команд и сообщит своё состояние. При обычном запуске скрипта интерпретатор этого не делает, поэтому запуск может завершиться ошибкой тайм-аута 1053.



В Python-службе библиотека pywin32 обеспечивает взаимодействие с SCM.



\### 2. Почему sc.exe не видит работающую задачу PowerShell?



PowerShell-скрипт зарегистрирован как задача Планировщика заданий, а не как служба SCM. Поэтому он может работать в фоне, но `sc.exe query` возвращает ошибку 1060. Запуском задачи управляет Планировщик заданий Windows.



\### 3. Что такое Execution Policy?



Execution Policy — политика выполнения скриптов PowerShell. Она определяет условия, при которых PowerShell разрешает выполнение сценариев.



В этой работе параметр `-ExecutionPolicy Bypass` был указан только для процесса, запускающего учебный скрипт. Общая политика выполнения в системе не изменялась.



Execution Policy не является полноценной границей безопасности: необходимо проверять содержимое запускаемых скриптов.



\## Результат



На практике запущены фоновая задача PowerShell и служба Python. Их работа проверена по состоянию и содержимому логов. Установлено, что задачей управляет Планировщик заданий, а службой — SCM.
